# T6.1-B — Карта (поток B из T6.0, дефект 3)

Статус: код готов, гейты зелёные. Проверка на устройстве — за человеком (нет доступа к симулятору/телефону).

## Что сделано

### 3a. Пустая карта (главная причина)
`fitToCoordinates` вызывался безусловно и не имел нижней границы охвата — на вырожденном наборе точек
(в проде: две карточки в 3·10⁻⁸° друг от друга) карта уходила на зум, где тайлов не существует.

- `apps/mobile/src/lib/geo-math.ts`: добавлены `MIN_FIT_SPAN = 0.004` (~400 м) и `fitSpan(points)` — наибольший
  разброс широты/долготы набора точек, с той же обработкой антимеридиана, что и в `boundingRegion`.
- `apps/mobile/src/screens/MapScreen.tsx`: в `useEffect` после `onMapReady` теперь ветвление — при одной точке
  или `fitSpan(points) < MIN_FIT_SPAN` карта подгоняется через `animateToRegion(boundingRegion(points))`
  (там есть `minDelta`), иначе — как раньше, `fitToCoordinates`.

### 3b. Зон нет
`completedCells` показывал полигон только при 100 % закрытии дневника — на практике почти никогда.

- `apps/mobile/src/lib/diary.ts`: новая `visitedCells(diary, cards)` рядом с `completedCells` — возвращает
  **все** ячейки, где найдена хотя бы одна ожидаемая порода (`{ cell_id, found, total, complete }`).
  `completedCells` не тронута (используется тестами, оставлена как есть).
- `apps/mobile/src/screens/MapScreen.tsx`: полигоны теперь строятся из `visitedCells`, с градацией —
  закрытая (`complete`) заливка/обводка как раньше (`mapColors.cellFill/cellStroke`), посещённая — тусклая
  заливка `colors.accentTint` + пунктирная обводка `colors.accentBorder` (`lineDashPattern`). Обе краски уже
  были в `theme.ts` — файл не трогал (вне границ потока).
- Легенда: строка счётчика показывает отдельно «N ячеек закрыто» и «M ячеек посещено»; в ряд легенды
  добавлен второй квадрат-образец (пунктирный) с подписью «есть находки».

### 3c. Совпадающие маркеры
- `apps/mobile/src/lib/geo-math.ts`: `groupByLocation(points, precision = GROUP_PRECISION)` — группировка по
  координатам, округлённым до 5 знаков (~1 м), порядок групп по первому вхождению. Библиотека кластеризации
  не подключалась.
- `apps/mobile/src/screens/MapScreen.tsx`: один маркер на группу; при `count > 1` в кружке вместо пустого/«?» —
  число находок. Тап: одна карточка — сразу открывается; несколько — собственный лист выбора
  (`Modal` + `ScrollView`, строки `displayName` / тир, точка цвета тира, шеврон, «Отмена»).

## Как проверить
- `pnpm --filter mobile typecheck` — зелёный.
- `pnpm --filter mobile test` — зелёный, включая новые тесты `groupByLocation`.
- `pnpm lint` (из корня) — зелёный.
- `cd apps/mobile && npx expo export --platform ios` — сборка проходит; `dist/` удалён после проверки.
- На телефоне (за человеком): открыть вкладку «Карта» — должен появиться маркер-счётчик «2» в районе
  Тбилиси (а не серый пустой экран), ячейка `szrv5f` подсвечена тусклой пунктирной заливкой с подписью
  в легенде «1 ячейка посещена», масштаб — район города. Тап по маркеру-счётчику — список из двух карточек.

## Принятые решения
- `completedCells` оставлена нетронутой (не удалялась и не рефакторилась в терминах `visitedCells`), чтобы
  не расширять диff за пределы границ потока и не трогать её существующие тесты/семантику.
- Группировка координат — округление до 5 знаков (~1 м), как явно указано в диагнозе; проверка на равенство
  строкового ключа, а не кластеризация по расстоянию. Перед `toFixed` координата прогоняется через
  `Math.round`: иначе точки чуть западнее нулевого меридиана дают ключ `-0.00000` и не склеиваются с соседями.
- Цвета для «посещена, но не закрыта» взяты из уже существующих токенов `theme.ts`
  (`colors.accentTint`, `colors.accentBorder`) — новых токенов не заводил, чтобы не выходить за границы
  файлов потока (`theme.ts` не в списке разрешённых).
- `animateToRegion` для вырожденного набора вызывается с `animated ? 350 : 0` мс — так же, как раньше решала
  анимацию логика `fitToCoordinates` (первая подгонка — без анимации, последующие — с).

## Ревью и правки после него

Ревью первой версии вернуло **NEEDS_WORK** с одним major. 3a и 3b приняты полностью.

**Major (исправлено).** Выбор карточки из группы был сделан на `Alert.alert`, а на Android React Native
режет список кнопок до трёх и остальные молча отбрасывает. На паре сканов (диагностированный случай) это
работало, но при трёх и больше находках в одной точке часть карточек стала бы недостижима без всякого
сообщения — то есть критерий 3c «тап по группе даёт выбор» выполнялся только для группы из двух.
Заменено на собственный лист выбора внутри экрана: `Modal` с затемнённой подложкой (тап по ней — закрыть),
прокручиваемый список всех карточек группы (`maxHeight: '70%'`, отступ снизу по `insets.bottom`), кнопка
«Отмена». Новых зависимостей нет, оформление — существующие токены `theme.ts` и `Chevron` из `components/ui`.

**Minor (исправлено).**
- Группировка `markerGroups` жила в экране и потому не была покрыта тестами — ровно поэтому лимит кнопок
  Android и не поймался автоматически. Вынесена в `lib/geo-math.ts` как `groupByLocation`, тесты покрывают
  группы размера 1, 2 и 5, нулевой меридиан и пустой вход.
- `fitSpan` дублировала обработку антимеридиана из `boundingRegion`. Обе теперь считают габариты через общий
  внутренний `bounds(points)`; поведение прежнее, тесты обеих функций не менялись и проходят.

**Minor (оставлено осознанно).**
- `MIN_FIT_SPAN = 0.004` — эвристика: подобрана по порядку величины (~400 м), не измерена на устройстве.
  Проверяется вместе с остальной приёмкой пункта 3 вручную; ошибка в ту или иную сторону не ломает карту,
  а лишь меняет стартовый масштаб вырожденного набора.
- `visitedCells` и `completedCells` строят `byCell` каждая по-своему. Сводить не стал: `completedCells`
  покрыта своими тестами и используется вне этого потока, а выигрыш — несколько строк.
