## Формат манифеста (по образцу `supabase/seed/golden/labels.json`)

```json
{
  "version": 1,
  "generated_at": "2026-09-30T11:34:31.319Z",
  "items": [
    {
      "id": "<scan_id>",
      "file": "<scan_id>/0.jpg",
      "photos": ["<scan_id>/0.jpg", "<scan_id>/1.jpg"],
      "rock_class": "basalt",
      "label_source": "user_confirm",
      "matched_model": true,
      "verdict": { "provider": "anthropic", "model": "claude-sonnet-5", "prompt_version": "main-v3" }
    }
  ]
}
```

`file`/`rock_class` совпадают по смыслу с golden-набором (общий код чтения — задача на потом: golden-загрузчик
живёт в `apps/worker/**`, вне границ этой задачи). `id` — `scan_id`, а не `user_id/scan_id`: путь фото в
выгрузке намеренно без идентификатора пользователя (доп. приватность сверх минимума).

## Правила отбора и как они проверены

Из `docs/tasks/T7.1-own-model-groundwork.md` §3, дословно как жёсткие условия в `isEligible`:
`training_opt_in = true` (текущее значение на момент запроса — отозвавшие уже не проходят) **и** есть строка
в `lithos.labels` **и** карточка существует, не `hidden`, `verification ≠ pending_review`. Каждый пункт —
отдельный тест в `dataset-export.test.mjs` (без согласия / без метки / hidden / pending_review / карточки нет
вовсе — все пять не проходят). Происхождение (`label_source`, `matched_model`, `verdict.provider/model/
prompt_version` из `lithos.scan_results`, приоритет ступени `escalation > main > gate`) — отдельные тесты на
`pickLabel`/`pickVerdict`. Воспроизводимость — тест `buildManifest` на одних данных в разном порядке строк:
результат побайтово одинаков (кроме `generated_at` — это метка времени запуска, не данные, инъецируется
аргументом, а не читается из часов внутри чистой функции).

## Счётчик готовности

`pnpm dataset:readiness` — таблица «порода → число подтверждённых фотографий» (не сканов — именно файлов),
общее число фото, число сканов, и отдельно число `training_opt_in = true` пользователей (это не то же самое,
что число, у кого уже есть подтверждённые фото, — показывает, будет ли набор расти). Проверено на проде:
сейчас 0/0/0 — честно и без падения.

## Фотографии и служебный ключ

Скачивание — прямой `fetch` на Storage REST (`SUPABASE_URL` + `SUPABASE_SERVICE_KEY`/`_ROLE_KEY`), без
`@supabase/supabase-js` в корневом `package.json` (не тащим новую зависимость в root ради одного скрипта).
Таймаут 15 с, 3 попытки, экспоненциальный бэкофф — как требует CLAUDE.md для внешних вызовов. Нет ключа в
`.env` → скрипт печатает это по-русски и выгружает манифест без фото, не падает (проверено).
