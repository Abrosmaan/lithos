## Что сделано

Экраны **Camera → Review → Result(заглушка)** на react-navigation (native-stack), S0 Preflight на клиенте, отправка скана в Supabase (`lithos.scans` + Storage + `lithos.scan_photos` + RPC `enqueue_scan`). Идемпотентно по `scan_id`. Плюс одна миграция `0003` (политика UPDATE на Storage — без неё повтор загрузки по тому же пути падал по RLS).

## Решения

- **Blur-детект — jpeg-js на копии 128 px** (вариант (б)): `expo-image-manipulator` пикселей не даёт, `expo-gl` — тяжёлая нативка ради одного фильтра. Порог **25** калиброван на синтетической многооктавной текстуре (шум 4–256 px + резкий круг + трещины; gaussian σ в масштабе 1024, измерение на копии 128):

  | контраст | σ0 | σ1.5 | σ3 | σ5 | σ8 | σ12 |
  |---|---|---|---|---|---|---|
  | 0.35 | 43 | 40 | 29 | 18 | 9 | 5 |
  | 0.7 | 100 | 81 | 62 | 38 | 18 | 8 |
  | 1.0 | 193 | 171 | 119 | 70 | 27 | 11 |

  Порог консервативный: отсекаем явно размытое (σ ≥ 8) и плоские кадры (стена → 0); пограничное доверяем S1 Gate (`quality=blurry`). Ложный отказ резкому малоконтрастному камню хуже лишнего вызова Gate за $0.002. Низкая variance при средней яркости < 40 трактуется как «темно/нет деталей» — отдельный текст. **Уточнить на golden set (T2.4).**
- **UUID v5 — своя реализация** вместо пакета `uuid` (тому нужны полифилы random). RFC требует SHA-1 от байтов namespace + UTF-8(name); `digestStringAsync` хэширует строку, поэтому взят `Crypto.digest(SHA1, bytes)` того же expo-crypto. Проверено на эталоне RFC 4122 `v5(DNS, "www.example.com") = 2ed6657d-e927-568b-95e1-2665a8aea6a2` (совпадает с пакетом `uuid` и Python `uuid5`; значение `…95e3-fa5c2ba5f2a1` из постановки ревью — не эталон). Namespace проекта `3b0d6f52-9c4e-4a8b-9f1e-7c2a5d8e1b64` — не менять. Имя: `${device_id}|${timestamp ISO}`.
- **`.env` — не симлинк, а файл, сгенерированный `scripts/sync-env.mjs`** (только `EXPO_PUBLIC_*`). Симлинк на корневой `.env` тащил бы все секреты проекта в процесс Metro/EAS ради двух публичных значений. Генерация — в `pre*`-скриптах, поэтому `pnpm --filter mobile start/ios/android/web/export` всегда актуальны.
- **Расхождения со spec/pipeline (dev-plan §5.1):**
  - spec §4.1 «1–4 фото, обязательно одно с масштабом» → реализовано **до 3** (dev-plan T1.4, ai-pipeline S2 «до 3 фото») и масштаб — **предупреждение, не блокировка** (`has_scale_photo` уходит в `user_tests`; штраф/бонус — дело Rules).
  - ai-pipeline §3 S0 «гео + время + user_id → scan_id» → реализовано **uuid v5(device_id | timestamp)** по dev-plan T1.4/миграции 0001 (комментарий к `scans.id`). Гео в ключ не входит: отказ от гео не должен менять идемпотентность.
- **scan_id создаётся один раз на попытку** и живёт в черновике до успешной отправки; любое изменение фото/тестов — новый id. Повтор после сбоя → тот же id → без дублей. (После kill-а приложения черновик теряется — новый скан; дедуп по pHash — воркер T2.1.)
- **`scans`: insert с `ignoreDuplicates` + `update … where stage='preflight'`** — клиент никогда не откатывает `stage`, принадлежащий воркеру.
- **`is_primary` = самое резкое фото** (та же variance) — ai-pipeline §3 S1 «лучшее по резкости».
- **`scan_photos` без уникального ключа** по пути и без delete в RLS → `id` строки детерминирован (uuid v5 от `photo|scan_id|storage_path`) и upsert с `ignoreDuplicates`: повтор после таймаута не даёт дубля даже если первый insert доехал до сервера. Миграция `unique (scan_id, storage_path)` остаётся желательной страховкой, но не обязательна.
- **`storage.upload` не принимает AbortSignal** (`FileOptions` без него): 60-секундный таймаут отклоняет только обёртку, запрос доезжает сам; повтор безопасен благодаря `upsert: true` + политике 0003. Полноразмерный кадр `takePictureAsync` удаляется сразу после preflight, копия 1024 px — при удалении из черновика/после отправки.
- **Гео при отказе — не блокер** (spec §4.1): баннер + подтверждение «Продолжить без гео».
- `UserTests` — type-only импорт из `@lithos/shared` (Metro его не резолвит).
