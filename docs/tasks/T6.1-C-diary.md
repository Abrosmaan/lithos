# T6.1-C — Дневник места: топоним + фото находок

Статус: **готово** · поток C из `docs/tasks/T6.0-fixes-and-social.md` (дефект 4).

## Результат

1. **Тесты `lib/place-name.ts`** (`lib/place-name.test.ts`, 22 теста): чистые хелперы
   (`placeNameFromAddress` — приоритет `district+city → city → district → subregion → region`,
   дедуп при `district === city`, игнор пустых/пробельных строк; `pickPlaceName` — первый осмысленный
   адрес из списка), `fallbackPlaceName`/`placeCacheKey`, и поведение `placeNameForCell` с
   инжектированными геокодером/хранилищем (без сети и AsyncStorage):
   - невалидный geohash → fallback без обращения к зависимостям;
   - успешный геокодер → имя кладётся в store;
   - имя из store → геокодер не вызывается (кэш реально спасает от повторного вызова);
   - повторный вызов в том же процессе (память модуля) → геокодер не вызывается второй раз;
   - параллельные вызовы по одной ячейке возвращают один и тот же inflight-промис и бьют в
     геокодер один раз (дедупликация подтверждена по счётчику вызовов и по референсному равенству
     промисов);
   - пустой ответ геокодера → fallback, не кэшируется;
   - геокодер бросает / store бросает → не пробрасывается, резолвится fallback'ом/именем.

   Дефектов в `place-name.ts` не нашёл — модуль не переписывал, использовал как есть.

2. **`DiaryScreen.tsx` — топоним**: добавлен `useEffect`, ключ — `data?.cellId`; при смене ячейки
   (переключатель «моё место» / «ячейка карточки», смена гео) состояние `placeName` сбрасывается
   в `null` и запрашивается заново через `placeNameForCell`, guard по `alive`-замыканию отбрасывает
   устаревший ответ. Заголовок карточки ячейки: `placeName ?? fallbackPlaceName(cellId)` —
   фолбэк виден мгновенно, без пустого состояния и без прыжков вёрстки. Мелкая mono-строка теперь
   `«{cellId} · {lat}, {lng}»` (например `szrv5f · 41.674, 44.823`) вместо голых координат;
   строка с источником ячейки (`SOURCE_RU`) показывается всегда, а не только при известном центре.

3. **Фото в «Находки в ячейке»**: по образцу `CollectionScreen` — состояние `urls`, после загрузки
   карточек ячейки (`load()`) вызывается `fetchPrimaryPhotoUrls(shown.map(c => c.scan_id))` (только
   по нескрытым карточкам, как и список плиток), `CardTile` получает `photoUrl={urls.get(c.scan_id)}`.
   Загрузка фото не блокирует появление карточки дневника (идёт после `setData`), гонки гасятся тем же
   `isAlive()`, что и остальная загрузка.
