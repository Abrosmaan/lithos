# T3.1 — Клиент: коллекция и дневник

Статус: **код готов, ревью-замечания закрыты, проверки зелёные; ждёт ручной проверки на телефоне** · 2026-09-08

## Что сделано

Таб-бар волны 3 (**Камера / Коллекция / Карта / Профиль**, `@react-navigation/bottom-tabs`), полноценный экран
**Коллекция** (сетка 2 колонки, фото по signed URL с кэшем, фильтр по тиру чипами, сортировка) и новый экран
**Дневник места** по ячейке geohash-6 (spec §8). Только `apps/mobile/**`; балансовых чисел в клиенте нет —
тиры, их порядок (`tierRank`) и русские названия берутся из `@lithos/shared`.

### Навигация
Корневой native-stack: `Tabs` (bottom-tabs: `Camera | Collection | Map | Profile`) + экраны поверх табов
`Review | Result | Card | Safety | Diary`. Детальные экраны открываются из любой вкладки (`navigate('Card')`
всплывает до корневого стека); переход на вкладку — `navigate('Tabs', { screen: 'Camera', params })`.
Кнопки «В коллекцию» / «Новый скан» / «Переснять» / экран безопасности переведены на этот вызов; кнопка
«Коллекция» с камеры убрана (теперь есть вкладка). Типы: `TabScreenProps<T>` (composite) и `RootScreenProps<T>`
в `src/navigation/types.ts`.

   Коллекция.
2. Коллекция: сетка по две плитки с фото; чипы «Все · N», «Легендарный · …» … «Без редкости · …» фильтруют;
   «Новые / По score / По тиру» меняют порядок. Родители после раскола (`hidden=true`) не показываются.
3. Приёмка T3.1: сделать 3 скана разных пород в одной точке → Коллекция → «Дневник места»: «3 из N», три позиции
   с ✓ (если породы совпали с ожидаемыми; иначе они в «Сверх списка»). В Table Editor: `lithos.diary` для
   `(user_id, cell_id)` — `found` содержит эти породы.
4. С карточки: «Дневник этого места →» — дневник ячейки карточки; ссылка «Показать моё текущее место».
5. Выключить сеть → Коллекция показывает кэш с пометкой «Нет связи — показана сохранённая коллекция».

## Ревью
1. **code-reviewer (субагент), NEEDS_WORK → исправлено.** Blocker: в React Navigation 7 `navigate('Tabs', …)` с экрана
   над табами **не** возвращается на существующие табы, а пушит второй `TabNavigator` (стек рос на каждый скан, «назад»
   вело на старый Result). Все переходы на вкладки — с `{ pop: true }` (проверено роутером: стек схлопывается до `Tabs`).
   Major: `GEOHASH_PRECISION` продублирована с воркером → вынесена в `packages/shared/src/geo.ts`; Android без ключа
   Google Maps — см. T3.2. Minor закрыты: `SHOWCASE_MAX` → `packages/shared/src/ui-constants.ts`; гонка параллельных
   `load` (фокус + pull-to-refresh) — счётчик запросов, побеждает последний; просроченные signed URL при сбое сети не
   отдаются; фолбэк ячейки дневника без гео берётся из сети, а не только из кэша; заглушка «Нет геопозиции» не затирает
   уже показанный дневник; `isGeohash` ограничен 12 символами, `cellPolygon` — только geohash-6; лишний `insets.bottom`
   в профиле; карта перецентрируется при изменении набора точек. Не закрыто (записано ниже): правило «`unknown*` не
   закрывает позицию» дублируется с воркером; `geo_cache.fetched_at` не учитывается; лимиты выборок без пометки.
2. **Ревью координатора: T3.1 NEEDS_WORK → исправлено.** Major: `budget_paused` был недостижим (воркер не меняет
   `stage`) — фаза `paused` в `resultPhase` по `scans.error`, экран с текстом паузы и «В коллекцию», тест. Minor: тест
   `limitErrorCode`; «Находки в ячейке» без hidden (в `found` — с ними); пометки на плитке; мёртвый `listCards()`
   удалён; спейсер при нечётной сетке; офлайн-фолбэк только на сетевых ошибках, кэш по `user_id`.

## Решения
- **Табы в корневом стеке, детальные экраны поверх табов** (а не стек в каждой вкладке): один экземпляр `Card`,
  без дублирования маршрутов, существующие `navigate('Card')` работают из любой вкладки; таб-бар на экранах
  результата/карточки скрыт — это модальные потоки. Переходы на вкладку явные (`Tabs → screen`).
- **Свой geohash вместо `ngeohash`**: пакет — зависимость воркера, не shared; 60 строк, сверены с ngeohash
  (`ucfv0n`, `u4pruydqqvj`, bbox `ezs42`).
- **`expected` из `geo_cache`, когда дневника ещё нет**: строка `diary` появляется только после первого скана
  в ячейке (воркер), а дневник по текущему месту должен что-то показывать до него. Если и `geo_cache` пуст — текст
  «нет данных о геологии, отсканируйте камень здесь».
- **`found` = дневник ∪ карточки в ячейке** — дневник у воркера пишется на `done`, карточки появляются раньше
  (escalation); объединение убирает рассинхрон. `unknown*` не засчитываются (как у воркера).
- **Фото в сетке — пакетно**, не `fetchScanPhotos` на каждую плитку (2 запроса × N карточек).
- **Иконки вкладок — эмодзи**: `@expo/vector-icons` не установлен; тянуть набор ради четырёх глифов не стали.

- Округление `limitErrorCode` по подстроке сообщения RPC — хрупкая связка с текстом `raise exception` в 0006.
