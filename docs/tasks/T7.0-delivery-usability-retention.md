# Часть 1. Доставка на телефон

## 1.0. Как есть сейчас

Проект EAS не заведён: в `apps/mobile/app.json` нет `extra.eas.projectId`. Сборок не было ни одной.
`expo-updates` не установлен. Значит всё, что запускалось на телефоне, это Expo Go поверх сервера разработки,
и компьютер нужен при каждом запуске.

`apps/mobile/eas.json` уже есть, в нём профили `preview` (internal) и `production` (store), но нет поля
`image` — без него сборка из веб-панели недоступна.

## 1.1. Обновления по воздуху

**Зачем.** Любая правка в коде приложения сейчас требует новой сборки. С `expo-updates` правки долетают на
телефон сами, без пересборки и без компьютера.

**Что сделать.** `npx expo install expo-updates`, настроить `updates.url` и `runtimeVersion` по инструкции EAS
Update, привязать канал к профилю сборки (`channel` в `eas.json` уже проставлен).

**Важно.** По воздуху едет только JavaScript. Новая нативная зависимость, изменение прав или версии SDK
по-прежнему требуют сборки. Это надо понимать заранее, чтобы не удивляться.

**Приёмка.** Правка текста на экране доезжает до установленного приложения без пересборки.

## 1.2. Первая сборка

**Что сделать.** `eas init` в `apps/mobile`, затем `eas build --profile preview --platform android` и
`--platform ios`. Переменные `EXPO_PUBLIC_*` завести через `eas env:create` для окружения `preview`.

**Android.** Профиль `preview` с `distribution: internal` даёт файл, который ставится по ссылке. Аккаунт
Google Play не нужен. Если сборка отдаст `.aab` вместо `.apk`, добавить в профиль `"android": { "buildType":
"apk" }`.

**iOS.** Нужен платный Apple Developer Program. Без него на iPhone остаётся только Expo Go с компьютером.
Это решение за Игорем: платить или пока жить на Android-сборке.

**Приёмка.** Приложение установлено на телефон и запускается без сервера разработки.

## 1.3. Сборка без компьютера

**Что сделать.** Добавить поле `image` в профили `eas.json`, подключить репозиторий к проекту Expo
(приложение Expo в GitHub + связанный аккаунт), после чего сборка запускается кнопкой «Build from GitHub»
из браузера, в том числе с телефона. Метки вида `eas-build-[platform]:[profile]` на pull request запускают
сборку автоматически.

**Ограничение из документации Expo.** Минимум одна успешная сборка через CLI должна быть сделана до этого,
отдельно для каждой платформы. То есть компьютер нужен ровно один раз, дальше нет.

**Приёмка.** Сборка запущена из браузера телефона и доехала до установки.

# Часть 2. Полная работоспособность

Ранжировано по тому, насколько это ломает реальное использование.

## 2.1. Аккаунт: коллекция не переживает переустановку

**Что не так.** Вход только анонимный. Переустановил приложение или сменил телефон — коллекция потеряна
навсегда, восстановить нечем. В `apps/mobile/src/lib/settings.ts` это честно помечено `APPLE_SIGNIN_SOON`,
кнопка в профиле отвечает «Скоро». Для прототипа терпимо, для живого пользователя это дыра номер один: он
теряет ровно то, ради чего играл.

**Как чинить.** Вход через Apple поверх существующей анонимной сессии, с превращением анонимного
пользователя в постоянного, а не с созданием второго. Порядок работы: сначала прочитать актуальные доки
Supabase про связывание личности с анонимным пользователем и доки Expo SDK 57 про `expo-apple-authentication`,
и только потом писать код. Ключевое требование: **ни одна карточка не должна потеряться при связывании**, и
сценарий «анонимная коллекция на телефоне A, вход на телефоне B» должен иметь определённое поведение,
записанное в артефакте.

**Compliance.** Появляется новая сущность данных, значит правится `docs/legal/data-map.md` и раздел про
идентификаторы в политике. Тексты экрана входа — в `docs/legal/consent-copy.md`, как и всё остальное.

**Приёмка.** Переустановка приложения с входом через Apple возвращает ту же коллекцию. Тест на чистую логику
связывания зелёный.

## 2.2. Карта на Android пустая

**Что не так.** В `apps/mobile/app.json` нет `android.config.googleMaps.apiKey`. На iOS карта работает через
Apple Maps без ключа, на Android без ключа будет пустой серый прямоугольник.

**Как чинить.** Получить ключ Google Maps для Android, положить в конфигурацию приложения через переменную
окружения EAS, а не строкой в репозитории.

**Приёмка.** На Android-сборке видны точки и ячейки.

## 2.3. Запасной провайдер моделей

**Что не так.** Ключ Google теперь есть и smoke-тест прошёл, но прогон эталонного набора на Google не делался,
решение по ступеням не принято, и на VPS ключа нет. Пока его там нет, при сбое Anthropic пользователь получит
отказ вместо карточки с пометкой «предварительно», то есть заявленный запасной путь не работает.

**Как чинить.** `pnpm eval --concurrency 3` (≈ $1.7 по оценке T4.2), сравнить точность, стоимость и задержку
с базовым прогоном Anthropic из `docs/tasks/T2.4.md`, принять решение по `STAGE_*`, положить ключ в `.env` на
VPS и перезапустить воркер.

**Приёмка.** Отключение основного ключа на VPS даёт карточку через Google с пометкой «предварительно», как
описано в сценарии T4.2, пункт 7.

## 2.4. Жалобы некому смотреть

**Что не так.** Таблица `lithos.reports` наполняется, автоскрытие по трём жалобам работает, но посмотреть
жалобы нельзя ничем: интерфейса нет, а прямого доступа к таблице у владельца в приложении нет по построению.
Пока пользователь один, это неважно; как только появится второй, это становится обязательным.

**Как чинить.** Минимальный инструмент, без экрана в приложении: скрипт в `scripts/`, который читает жалобы
через service_role и печатает таблицу «карточка, сколько жалоб, скрыта ли, тексты». Полноценную очередь
модерации не делать, это преждевременно.

**Приёмка.** Скрипт показывает жалобы и состояние публикации по каждой.

## 2.5. Юридические заготовки

**Что не так.** Незаполненных мест тридцать три, и они видны прямо в приложении на экране документов.
С ними нельзя ни в стор, ни отдать приложение постороннему человеку.

**За человеком** (список в `docs/legal/README.md`): оператор данных, юрисдикция, возрастной ценз, лицензия на
опубликованные фотографии, публичная страница с политикой. После заполнения перегенерировать копии в
`apps/mobile/src/legal/` — их идентичность источникам проверяется тестом.

## 2.6. Светлая системная тема при тёмном интерфейсе

**Что не так.** В `app.json` стоит `"userInterfaceStyle": "light"`, а интерфейс тёмный. Стоит проверить на
устройстве, не вылезает ли это в системных элементах: строка состояния, клавиатура, системные диалоги.

**Приёмка.** Скриншоты на устройстве, решение записано в артефакт.

# Часть 3. Интерес пользователя

Проверено по коду: достижений, серий, целей, кнопки «поделиться», лайков и счётчика просмотров нет вообще.

Главная проблема не в количестве механик, а в том, что **публикация уходит в пустоту**. Человек нажал
«опубликовать» и в ответ не происходит ничего. Он не узнаёт, увидел ли его находку хоть кто-нибудь. Пока эта
петля не замкнута, остальные украшения бессмысленны.

## 3.1. Счётчик просмотров публикации

**Зачем.** Самая дешёвая обратная связь автору. Один раз показанное «вашу находку смотрели 7 раз» делает
публикацию осмысленной.

**Как.** Серверная функция отметки просмотра по идентификатору карточки, уникально на зрителя, счётчик в
публичном представлении. Свои просмотры не считать. **Наружу отдаётся только число**, никогда не список
зрителей: кто смотрел — это данные третьих лиц, и в карте данных такого разрешения нет.

**Compliance.** Новая сущность, значит `data-map.md` и политика правятся в той же задаче, а не потом.

**Приёмка.** Счётчик виден автору на своей карточке, не растёт от собственных открытий, тест на серверную
логику зелёный.

## 3.2. Поделиться карточкой наружу

**Зачем.** Самый дешёвый рост и единственный повод показать приложение друзьям. Сейчас показать находку
нечем вообще.

**Как.** Картинка карточки плюс системное меню «Поделиться». Проверить, что выбранный способ съёмки экрана
работает в Expo Go и в сборке. Делиться можно и неопубликованной карточкой: это собственный контент
пользователя, но в этом случае картинка не должна содержать точных координат.

**Приёмка.** Картинка уходит в мессенджер, координат на ней нет.

## 3.3. Редкость находки относительно других

**Зачем.** Тир говорит, насколько камень хорош сам по себе, но не говорит, насколько он редок среди находок
остальных. «Такую породу находили 3 раза из 400» — сильная эмоция, и данные для неё уже лежат на сервере.

**Как.** Серверный агрегат по опубликованным находкам, только числа, никаких чужих карточек. Балансовых чисел
не заводить: это статистика, а не правило начисления.

**Приёмка.** Строка на карточке появляется, когда выборка достаточна, и честно молчит, когда данных мало.

## 3.4. Цель в коллекции

**Зачем.** Сейчас коллекция это просто список. Дневник места наполовину решает задачу, но только для одной
ячейки в километр, и цели за пределами текущей точки нет.

**Как.** Обобщить дневник до района: ожидаемые породы по более крупной ячейке, прогресс «собрано 6 из 14».
Использовать уже готовые данные Macrostrat и уже написанную логику дневника, новых источников не заводить.

**Приёмка.** В коллекции виден прогресс по району, он сходится с дневниками отдельных ячеек.

## 3.5. Чего сознательно не делаем сейчас

Уведомлений нет. Ленты нет. Лайков и комментариев нет. Причина одна: сначала нужен сигнал, что людям вообще
интересно публиковать, и его даёт счётчик просмотров из 3.1. Добавлять причины возвращаться раньше, чем
появилось ради чего возвращаться, значит строить на пустом месте.

# Часть 4. Хвосты ревью T6.1

Мелкие, зафиксированные в артефактах предыдущей волны. Брать попутно, отдельной задачи не заслуживают.

| Что | Где | Почему отложили |
|---|---|---|
| Строки настроек не гаснут во время удаления данных | `ProfileScreen`, `components/SettingsList.tsx` | нужен параметр `disabled` в общем компоненте |
| Нет проверки «экран ещё смонтирован» после await | `CardScreen`, `ProfileScreen` | безвредно на текущей версии React, но расходится со стилем файла |
| `noNameNote` хранит формулировку обрывком фразы | `lib/consent.ts`, `docs/legal/consent-copy.md` | именно эта форма и привела к обрезу текста согласия |
| `publish_card` возвращает всю строку карточки | миграция, новая | сужение требует пересоздания функции |
| Подпись кнопки жалобы расходится с документом | `PublicFindScreen` | правка на одну строку, нужно решение владельца |
| Два механизма доступа к фото вместо одного | `docs/tasks/T6.1-D-publish-server.md` | **вопрос владельцу**, обоснование записано там же |

# Часть 5. Как исполнять

## 5.1. Порядок

Часть 1 первая и целиком: без неё любая следующая правка не доезжает до телефона, и проверять придётся снова
через компьютер. Дальше 2.1 (аккаунт), потому что это единственный пункт, где пользователь теряет данные.
Затем 2.3 и 2.2 (провайдер и карта), затем 3.1 (просмотры) и 3.2 (шеринг). Всё остальное после.

## 5.2. Потоки для параллельных агентов

| Поток | Файлы | Зависимости |
|---|---|---|
| **A. Доставка** | `app.json`, `eas.json`, `package.json`, документ по сборке | нет, но много ручных шагов человека |
| **B. Аккаунт** | новый экран входа, `lib/auth.ts`, `ProfileScreen`, `docs/legal/*` | нет |
| **C. Провайдер и карта** | `.env` на VPS, `app.json` (ключ карт), артефакт прогона | нет |
| **D. Просмотры** | новая миграция, `lib/publish.ts`, `CardScreen`, `docs/legal/*` | нет |
| **E. Шеринг** | `CardScreen`, новый модуль, зависимость на съёмку экрана | нет |
| **F. Редкость и цель** | новая миграция, `lib/diary.ts`, `CollectionScreen` | после D по порядку миграций |

Правило прежнее: границы по файлам не пересекаются, каждый поток оставляет артефакт `docs/tasks/`, ревью
субагентом `code-reviewer`, правки тем же агентом, который писал.

## 5.3. Гейты

`pnpm typecheck` · `pnpm test` · `pnpm lint` · `cd apps/mobile && npx expo export --platform ios` с удалением
`dist`. Миграции через `pnpm db:migrate`, только новые файлы. Секреты не коммитить.

## 5.4. Что требует человека, а не агента

- Решение по Apple Developer Program (иначе на iPhone только Expo Go).
- Ключ Google Maps для Android.
- Заполнение юридических документов.
- Ответ по двум механизмам доступа к фотографии (часть 4).
- Подтверждение на устройстве после каждой части.
