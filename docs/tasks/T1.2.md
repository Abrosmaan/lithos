# T1.2 — Геоконтекст

Статус: **готово** (после ревью, 2 итерации) · 2026-09-07

## Что сделано

`getGeoContext(lat, lng): Promise<GeoContext>` (`apps/worker/src/geo.ts`):
валидация координат → geohash-6 (`ngeohash`) → `lithos.geo_cache` (fetched_at < 30 дней → `source='cache'`) → Macrostrat по **центроиду ячейки** (центр + 4 пробы) → нормализация → upsert в `geo_cache` → `source='macrostrat'`.

Деградация без исключений: при отказе Macrostrat — просроченная строка кэша любой давности (`source='cache'`, «предварительно»), иначе `expected_rocks=[]`, `setting=null`, `age_range=null`, `source='none'`; wanderers в этом случае только по широте (`glacial_erratic` при |lat| > 45°). Центр без единого юнита (Macrostrat не покрывает точку — большая часть Азии/Африки) — тоже `source='none'`, не вода. Отказ и «нет данных» помнятся в памяти процесса 60 с (`NEGATIVE_TTL_MS`), чтобы каждый скан не платил полный retry-бюджет. Параллельные промахи одной ячейки дедуплицируются (in-flight map). Сбой БД (чтение/запись) — warn в лог, ответ отдаётся. Строки кэша фильтруются по актуальным `ROCK_CLASSES`/`WANDERER_MECHANISMS` (enum мог измениться после записи).

Новых колонок не понадобилось — миграции нет: `macrostrat_json` хранит урезанный сырой ответ (только используемые поля юнитов, центр + пробы, ≈5–25 КБ на ячейку), остальные колонки — нормализованный результат.

### Файлы
- `apps/worker/src/geo.ts` — вход, кэш (`lithos.geo_cache`, select с TTL / без TTL для fallback / upsert `on conflict (cell_id)`), дедуп, негативный кэш, деградация. Экспортирует `readCache`/`writeCache`/`deleteCache`/`normalize`/`resetGeoMemory` для тестов и `check.ts`.
- `apps/worker/src/geo/macrostrat.ts` — HTTP-клиент. Центр: таймаут 10 с, 3 попытки; пробы: 5 с, 2 попытки; общий бюджет `fetchRaw` 30 с (один `AbortSignal`). Backoff 500·2ⁿ мс + jitter (`retryPolicy.backoffBaseMs`, тесты ставят 0). Ретраи только на сеть/таймаут/429/5xx, 4xx — сразу ошибка. База: `MACROSTRAT_BASE` → `MACROSTRAT_API` (имя переменной в текущем `.env`; `.env.example` знает только `MACROSTRAT_BASE` — привести к одному имени при следующей правке `.env`) → `https://macrostrat.org/api/v2`, читается лениво. В лог — endpoint, сторона пробы и координаты с точностью 0.01°, без URL.
- `apps/worker/src/geo/normalize.ts` — чистая нормализация `MacrostratRaw → {expected_rocks, age_range, setting, wanderers} | null`.
- `apps/worker/src/geo/lith-map.ts` — таблица литология Macrostrat → `RockClass`; наборы generic-, ледниковых и речных литологий.
- `apps/worker/src/geo/macrostrat-liths.json` — снимок `/defs/lithologies?all` (214 записей: id, name, type, group, class). В `/geologic_units/map` поле `liths` — **массив id**, не объекты с name/prop; `prop` API не отдаёт.

- `apps/worker/src/geo.test.ts` — 26 unit-тестов: мок `fetch` из фикстур (матчинг по endpoint и координатам с допуском 0.01°), мок `pool` с `fetched_at` и TTL (`vi.mock('./db.js')`).

## Нормализация

**Литологии юнита.** `liths[]` (id) → справочник; если id нет — парсим строку `lith` (токены «tuff group», «carbonates», «olivine basalt» нормализуются к именам справочника, «tholeiit*» → basalt). Веса: `Major:{…}, Minor{…}` → Major делят 0.7, Minor 0.3 (`MAJOR_WEIGHT`); иначе поровну.

**Generic-литологии** (обобщённые: «sedimentary», «volcanic», «mafic», «metamorphic», реголит, аллювий, тилл; и «не породы для коллекции»: эвапориты, торф, битум, илы, бокситы) — одно правило: если конкретная литология есть хоть где-то (центр или любая проба), generic отбрасываются — и внутри конкретного юнита (веса перенормируются), и юниты целиком; если конкретных нет нигде — `unknown_igneous|sedimentary|metamorphic` по `class`.

**Доли.** Центр — `CENTER_WEIGHT = 0.5`, сухопутные пробы (4 км по сторонам света, не море и не озеро) делят остальные 0.5 поровну; внутри группы юниты равновесны. Центр в воде (пустой юнит озера) — только пробы. Округление 0.001, сумма ≈ 1, сортировка по убыванию. Это приближение spec §6.3 «доля площади в радиусе водосбора» радиусом `PROBE_KM = 4` — без него камень из соседнего юнита в 4 км получал бы бакет «единичный» (30) вместо «обычный» (10).

**age_range** — по всем использованным юнитам (центр + пробы): `b_int_name` самого древнего – `t_int_name` самого молодого («Late Jurassic–Eocene»); одно имя, если совпадают; при отсутствии имён — «300–250 Ma»; иначе null.

**Таблица маппинга (кратко, полная в `lith-map.ts`).** Правило: если имя Macrostrat есть в `RockClass` — оно и берётся (marl, syenite, trachyte, migmatite, greywacke, ignimbrite, coquina, travertine, …); иначе ближайший класс. Осадочные: sand→sandstone, gravel→conglomerate, silt/loess→siltstone, mud→mudstone, clay→claystone, arkose/arenite/greensand/grit→sandstone, graywacke/wacke→greywacke, carbonate и все Dunham/Folk-классы→limestone, biomicrite/biosparite/encrinite→fossiliferous_limestone, dolostone/ankerite→dolomite, siderite/iron formation/laterite→ironstone, lignite/anthracite→coal, novaculite/radiolarite/porcellanite→chert, tufa→travertine, calcareous ooze→chalk. Магматические: monzogranite/syenogranite/leucogranite/alaskite/aplite/granophyre/quartz monzonite/charnockite→granite, monzonite→syenite, tonalite/trondhjemite→granodiorite, norite/troctolite/anorthosite→gabbro, dolerite/lamprophyre→diabase, все ультрамафиты→peridotite, rhyodacite/adakite→dacite, comendite→rhyolite, phonolite→trachyte, latite/trachyandesite/benmoreite/mugearite→andesite, basanite/tephrite/hawaiite/spilite/foidite→basalt, ash/tephra/tuffite/bentonite→tuff, welded tuff→ignimbrite, hyaloclastite/agglomerate→volcanic_breccia, volcanic glass→obsidian; foidolite/carbonatite→unknown_igneous. Метаморфические: ortho/paragneiss/granulite→gneiss, diatexite→migmatite, greenschist/blueschist/metapelite→schist, metabasalt→greenstone, metagabbro/metabasite→amphibolite, skarn/granofel→hornfels, metaconglomerate→quartzite, metagraywacke→greywacke, metasiltstone→slate, cataclasite/phyllonite/pseudotachylite→mylonite, fault breccia→breccia; metarhyolite/fault gouge→unknown_metamorphic.

## Эвристики setting и странников

Пробы: 4 точки в `PROBE_KM = 4` км (широта клампится, долгота заворачивается, у полюсов сдвиг ≤ 1°). Высота — `/mobile/map_query_v2`.
- **Море** рядом: проба с высотой < 0, либо высота = 0 при центре на суше с юнитами (Дорсет: глобальная карта рисует шельф как сушу, поэтому только по юнитам не работает).
- **Озеро**: проба с юнитами-пустышками (без имени и литологий — так Macrostrat рисует озёра) или именем sea/ocean/lake при высоте > 0 (Байкал: 449 м); либо центр в такой пустышке.
- Проба без юнитов и без отрицательной высоты — **не вода** (пустая карта ≠ озеро). Центр без юнитов — `source='none'`.

Приоритет `setting`: `coast` → `lake` → `river` (литология alluvium или alluvi*/fluvial/floodplain в `name`/`strat_name`/`lith`; `descrip` не используем — шумит) → `glacial` (till/tillite/diamicton/drift или glaci*/till/moraine/outwash/diamict* в тех же полях) → `volcanic` (доля вулканических литологий ≥ `VOLCANIC_SHARE = 0.5`) → `glacial` (|lat| > `GLACIAL_LATITUDE = 45`, без литологических признаков) → `inland`. `lake` добавлено сверх перечня spec (список открытый), чтобы не давать `drift_pumice` на озёрах.

Странники (`wanderers`, порядок как в `WANDERER_MECHANISMS`): `drift_pumice` — море рядом; `glacial_erratic` — |lat| > 45° или ледниковая литология; `river_transport` — река/аллювий. **`human_imported` по умолчанию не выдаётся** (решение ревью: иначе любое несовпадение «объясняется» и обходит антифрод spec §11); значение остаётся в enum для ручного/будущего использования. Inland без признаков → `wanderers = []`. Флаги считаются независимо от выбранного `setting`.

Константы: `GLACIAL_LATITUDE=45`, `VOLCANIC_SHARE=0.5`, `CENTER_WEIGHT=0.5`, `MAJOR_WEIGHT=0.7`, `PROBE_KM=4`, `CACHE_TTL_DAYS=30`, `NEGATIVE_TTL_MS=60000`, `TOTAL_BUDGET_MS=30000`. Это параметры геоэвристик, не балансовые числа score (те — в `packages/shared/score.ts`).

## Решения
- **Запрос по центроиду ячейки**, а не по координатам скана: значение в кэше соответствует ключу и воспроизводимо, первый скан в ячейке не фиксирует геологию «своей» точки на 30 дней.
- **Пробы вместо OSM.** Береговая линия и «водосбор» — 4 пробы по 4 км: 0 новой инфры, 8 лишних запросов на новую ячейку раз в 30 дней.
- **Байкал даёт `unknown_sedimentary`.** Вокруг Листвянки у Macrostrat только обобщённый «Mesozoic sedimentary rocks»; реальные гнейсы/граниты Шарыжалгая в его данных отсутствуют. Осмысленнее — только со вторым геослоем.
- **Аризона: `Early Cambrian–Roadian`** — потому что возраст считается по всем пробам, а северная проба (дно каньона) — кембрий. Для дневника локации это правда: в 4 км есть и то и другое.
- Точки ниже уровня моря на суше (польдеры, Прикаспий, Мёртвое море) получат `coast` — известное ложное срабатывание по высоте; на озёрах/пустой карте ложных coast нет.

## Не сделано / открытое
- Русло реки без аллювия в юните не распознаётся (нужен OSM waterways). Ледниковая зона по литологии зависит от детализации карты; для |lat| > 45° эрратики даются всегда.
- Второй геослой (OneGeology/национальные карты) для регионов с обобщёнными юнитами (Байкал, Азия, Африка).
- Негативный кэш — только в памяти процесса; при рестарте воркера регион без данных снова стоит 9 запросов на первый скан.
- Кэш промпта геоконтекста на 5 минут (ai-pipeline §3 S2) — на стороне T1.3/T2.x.
- `MACROSTRAT_BASE` vs `MACROSTRAT_API` — оставить одно имя в `.env`/`.env.example` (файлы вне границ этой задачи).
- Новых зависимостей не требуется (`ngeohash`, `pg`, `dotenv` уже в `apps/worker`).
