## Что сделано в этой сессии

Все четыре экрана переписаны **только в композиции рендера** — вся логика загрузки/фокуса/офлайн-кэша/пагинации
перенесена без изменений (это специально проверено на каждом файле перед правкой).

### `screens/CollectionScreen.tsx`
H1 Playfair 27 + mono-счётчик (`cardsCountText`). Карточка-вход в дневник — квадратная иконка 38px
(`accentTint` фон, квадрат-рамка `accentBright`) вместо просто текста. Чипы тиров переведены на новый `Chip` с
раздельными `label`/`count` (было — счётчик руками вклеен в строку через « · »); чипы сортировки — на
`variant="sort"` (было — обычный `variant="filter"`, из-за чего они красились заливкой вместо компактного
подсвеченного стиля). Пустые состояния — «камень»-плейсхолдер (`placeholderStripes`), Playfair 20, текст,
кнопка — по образцу прототипа (строки 618–625).

### `screens/DiaryScreen.tsx`
Карточка ячейки: Playfair 22 название, mono-координаты, кнопка «моё место» на `surface2`, прогресс `N из M` mono
26 + полоска 8px на `track`, значок «🏅 Дневник закрыт» на `tierColors.legendary`. Список «Ожидаемые породы» —
строки с кружком-галочкой (найдено — `accentTint`/`accentBorder` + галочка из двух повёрнутых линий, не найдено
— `surface`/`divider`), вместо текстовых `✓`/`○`. «Сверх списка» — пунктирная рамка (`borderStyle: 'dashed'`,
`accentBorder`), было — просто `Line`. «Находки в ячейке» переведены на сетку `CardTile size="sm"` (было —
самодельная строка с `TierBadge`); отдельная информация «порода · дата», которая была в старой строке, в
`CardTile` sm не показывается (по дизайну плитки — только имя и тир) — минорная потеря детализации ради
визуальной консистентности со всеми остальными сетками приложения, решил в пользу консистентности.

### `screens/MapScreen.tsx`
Маркер — по прототипу двухслойный: внешнее кольцо 18px цвета `colors.bg` (тёмная обводка, как
`border: 2px solid #0b0f14` в прототипе) + внутренний цветной круг 14px; для `pending_review` внутри круга
глиф «?» mono — **этого не было в дообразцовом коде** (там просто плоский кружок с белой обводкой без глифа);
сверил с данными прототипа (`mapDots`: `mark: c.tier === 'review' ? '?' : ''`) — добавил как исправление, а не
просто рестайл. Легенда и баннер — на `Note`/mono-подписях вместо ручных `View`+фиксированных цветов.

### `screens/ProfileScreen.tsx`
Крупный рестайл + два новых блока из DESIGN_SYSTEM.md (экран 13), которых не было вообще:

- **Аккаунт**: «Анонимный профиль» / «Вход через Apple» — кружок-аватар, подпись, кнопка. Настоящего входа через
  Apple нет — по тапу на кнопку показывается `Alert` с текстом `APPLE_SIGNIN_SOON` («Скоро: вход через Apple…»,
  готовый текст из `lib/settings.ts`, подготовленного заранее). Переключатель `signedIn` — чисто визуальный (для
  показа обоих состояний кнопки/подписи), в БД ничего не пишет.
- **Настройки**: список `settingsRows()` (уже был готов в `lib/settings.ts`): «Сканов сегодня N из M»
  (`countScansToday()` + `scanLimitForAccount(profile.createdAt)` — лимит и его учёт первых 24 ч только из
  `@lithos/shared`), «Язык», «Уведомления» (не реализовано — тап даёт `Alert` «Скоро»), «Доступ к камере» /
  «Геопозиция» (реальные статусы через `Camera.getCameraPermissionsAsync()` и
  `expo-location.getForegroundPermissionsAsync()`, тап открывает системные настройки `Linking.openSettings()`),
  «О приложении» (версия через новый пакет `expo-constants`, тап — `Alert`), «Приватность и данные» (тап
  раскрывает `PRIVACY_TEXT` тем же текстом, что на экране приветствия — не дублировал строку), «Удалить все
  данные» (красный; `Alert.alert` с текстом `WIPE_DIALOG`, подтверждение вызывает `wipeLocalData()` — уже
  готовую функцию в `lib/profile.ts` — и сбрасывает навигационный стек на `Welcome` через
  `navigation.getParent()?.reset(...)`, а не просто `.navigate`, чтобы аппаратная кнопка «назад» на Android не
  возвращала на `Profile` со стёртыми локальными данными).
- Убрана строка «в Lithos с {дата}» — её нет ни в прототипе, ни в DESIGN_SYSTEM.md; посчитал лишней.
- `CardTile` для «Редчайшая»/«Самая далёкая» теперь передаёт `kind` (плашка на фото), а не только `caption` —
  в дообразцовом коде плашки не было, подпись показывалась только как заголовок секции сверху.

### Новая зависимость
`expo-constants` (`~57.0.17`, через `npx expo install` — версия подобрана под SDK 57) — только для версии
приложения на экране «Настройки»; `expo-camera`/`expo-location` уже были в проекте, использован их namespace
`Camera.getCameraPermissionsAsync` (не top-level экспорт, как ожидалось изначально) и
`getForegroundPermissionsAsync`.

## Проверка
```
pnpm --filter mobile typecheck   # зелёный
pnpm --filter mobile test        # 99 passed
pnpm lint                        # зелёный
cd apps/mobile && npx expo export --platform ios   # бандл собирается, dist удалён
```
Бандл проверен на секреты через `strings … | grep -E 'sb_secret_|sk-ant-|SUPABASE_SERVICE'`: единственное
совпадение — строковый литерал самого supabase-js (`key.startsWith("sb_secret_")`, проверка формата ключа), не
значение секрета; это уже документировано в `docs/tasks/T2.2.md` как безопасное. Реального секрета, ключа
Anthropic или `SUPABASE_SERVICE_KEY` в бандле нет — виден только публичный `sb_publishable_…` анон-ключ и URL
проекта, как и ожидается.

## Решения (кратко)
1. Дневник/Диаграмма находок — `CardTile size="sm"` вместо самодельных строк (консистентность, минус деталь «дата»).
2. Карта — глиф «?» в маркере на ревью добавлен как исправление по данным прототипа, не было в исходном коде.
3. Профиль — блоки «Аккаунт»/«Настройки» реализованы полностью честно: ничего не работающего не выдаётся за рабочее (вход через Apple и уведомления — явное «Скоро»).
4. Удаление данных — сброс стека навигации на root, не просто переход, чтобы не оставлять «мёртвый» Profile в истории.
5. `expo-constants` добавлен только под версию приложения — минимально необходимая зависимость.
