## Как запустить (человек)

```
# 1. Скачать фото (сеть, ~1–2 мин, Commons просит паузу между запросами — она есть)
pnpm --filter worker exec tsx src/eval/fetch.ts            # --dry-run покажет URL, --ids vc-01,vc-02 — выборочно
# 2. Проверить harness на синтетике (только gate, центы)
pnpm eval --synthetic
# 3. Полный прогон (нужны ANTHROPIC_API_KEY и GOOGLE_GENERATIVE_AI_API_KEY в .env; БД-переменные — для кэша геоконтекста)
pnpm eval                                                  # gate+main+escalation, 6 моделей × 60 фото
pnpm eval --stage main --limit 10                          # дёшево посмотреть
pnpm eval --stage escalation --models anthropic:claude-opus-5   # main (Sonnet 5 и 3.7 Flash по умолчанию) прогонится сам как prior
```
Ожидаемая стоимость полного прогона по §2a: Anthropic ≈ 60 × (0.002 + 0.025 + 0.045) ≈ **$4.3**, Google ≈ 60 × (0.0005 + 0.007 + 0.02) ≈ **$1.7**; escalation здесь идёт на все 60 позиций, а не на 10–15 %, поэтому дороже среднего скана. Отчёт и сырые ответы — `supabase/seed/golden/runs/<ts>/`.

## Решения

- **Источник фото — Wikimedia Commons, не Kaggle.** Dev-plan T2.4 называет «Kaggle-датасеты из переписки», но в репо/документах ссылок на них нет, а лицензии Kaggle-наборов обычно не позволяют класть фото в публичный репозиторий. На Commons у каждой позиции проверяемая CC-лицензия и автор (большинство — James St. John, геолог, ручные образцы; GeoDIL — учебная коллекция, CC0). Отклонение записано (dev-plan §5 п.1).
- **Разметка — не эксперт-геолог**, а описания авторов Commons (название файла = определение автора). Для §9 это «v0»; при расхождении с моделью по спорным позициям (lc-06 flint/chert, lc-09 marl, tr-05 малахит без породы-хозяина) смотреть фото, а не верить манифесту слепо. `acceptable_alternatives` заполнены с запасом именно поэтому.
- **Фото — ручные образцы, а не пляжные телефонные снимки.** Это делает golden set легче реального трафика (чистый фон, хороший свет). Слабые позиции помечены в `notes`: lc-09 (музейная мергелистая конкреция), tr-08 (бетонная плитка, а не окатанный бетон), tr-07/tr-10/tr-11/tr-12 (несколько объектов в кадре — gate может дать `multiple_objects`), gl-12 (полированный образец). Их и ещё пляжные фото имеет смысл заменить своими при полевом тесте.
- **Фото в git.** 60 × ≈150–300 КБ после сжатия до 1024 px ≈ 10–18 МБ < 50 МБ — `images/` не в `.gitignore`; `fetch.ts` печатает размер каталога и предупреждает, если > 50 МБ.
- **Точки — контрольные из T1.2 + две новые** (Йосемити, Таллин), проверенные по Macrostrat: гранитная река с настоящим гранитом в геоконтексте и ледниковый берег, где все 12 пород — эрратики (местная геология — известняк). Так golden set проверяет и `provenance.wanderer_mechanism`, а не только `rock_class`.
- **Без fallback внутри eval.** `callModel` умеет уходить на другого провайдера; в eval это смешало бы метрики двух моделей. Резолвер в `run.ts` знает только провайдера тестируемой модели, поэтому любой отказ = ошибка вызова этой модели (строка «Ошибок вызова»).
- **Escalation — на всех позициях**, а не на 10–15 % с триггерами S3: сравнить Opus 5 и 3.1 Pro нужно на одном и том же наборе, особенно на ловушках. Prior — main-модель той же роли и провайдера по умолчанию (`ROLE_MODELS`), чтобы сравнение семейств было честным (Anthropic-стек против Google-стека); `--models` на автодобавленную main не распространяется. Смешанные пары (prior Sonnet → Gemini Pro) не поддержаны; если понадобится — добавить `--prior-provider`.
- **Пороги только из shared** (`INCLUSION_CONFIDENCE_THRESHOLD`, `CONFIDENT_ERROR_THRESHOLD`); эквивалентности разметки — `VARIETY_BASE` (разновидности пород), `MINERAL_FAMILY` (семейства минералов) и regex процентов — живут в `metrics.ts`, это не балансовые числа. `ROCK_CLASS_BASE` из shared для точности не подходит (см. таблицу выше).
- **`.gitignore` для прогонов** — `supabase/seed/golden/runs/*/*` + `!…/runs/*/report.md` (вариант `runs/**` + негация не работает: git не заглядывает в исключённый каталог). Сырые ответы для калибровки хранятся локально; зафиксировать конкретный прогон — `git add -f`.
- **Формат каталога прогона** `runs/<ts>/<stage>/<provider>__<model>/<id>.json` (а не `<model>/<id>.json` из постановки) — одна модель теоретически может стоять на двух ступенях.
- **Стоимость/латентность** — из `CallModelOutput` (T1.3), то есть включают retry и repair; ошибочные вызовы в среднюю стоимость не входят, но считаются отдельно.
