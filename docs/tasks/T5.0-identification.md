## Решение

- **main-v2 принят** как рабочий текст (не закоммичен — по условию задачи). Цель задачи достигнута: распределение по кандидатам калибровано (сумма ∈ [0.85, 1.05] на 100 % позиций против 80 % у v1, «всем по 0.9» исчезло), у всех альтернатив есть `reason` для UX-списка `identificationCandidates` (spec §4.3: score от этих чисел не зависит — тиры не изменились). Уверенные ошибки 0 %. Цена: −1.8 п.п. top-1 (одна позиция, в пределах шума 60 фото), +21 % $/скан, +1.9 с p50 (латентность и так блокер T4.2 — см. T2.4; решать сменой модели, не промптом).
- Top-2 не вырос ни в v2, ни в v3: на этом наборе вторая позиция модели — «сосед» primary, а промахи межсемейные; прямое требование ставить межсемейную гипотезу второй (v3) вредит top-1. Дальше двигать top-2 промптом не стоит — это задача ступени escalation (в baseline Opus поднимал top-2 до 85.7 %) или геоконтекста.
- Precision включений упал с 78.9 до 57–64 % при recall +2 п.п.: v2 чаще называет включения ≥ 0.6 (28 против 19 предсказаний). Числа маленькие (15–16 верных), но тенденцию проверить на следующем прогоне; если подтвердится — добавить в правило про включения «report an inclusion at ≥ 0.6 only if you can point to it in the photo».
- Метрики «Калибровка», «P(истина)», «Альтернатив» — постоянные колонки отчёта; окно `CALIBRATION_SUM_RANGE` живёт в `metrics.ts` как допуск eval (не балансовое число, в `shared` не переносится).
- Промпт-версии: старые сканы в БД остаются с `main-v1`; `identificationCandidates` работает с обоими (у v1 остаток ≥ 5 % уходит в «другое»).
