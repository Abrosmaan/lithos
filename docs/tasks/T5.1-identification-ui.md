# T5.1 — Клиент: определение как список кандидатов с процентами (UX в духе iNaturalist)

Статус: **код готов, замечания ревью закрыты, проверки зелёные; ждёт ручную проверку на телефоне** · 2026-09-09
(id T5.0 занят промптами main-v2/v3 — `T5.0-identification.md`.)

## Что сделано

На экранах **Результат** и **Карточка** порода показывается не одной строкой, а списком кандидатов с процентами
(primary крупно, остальные тонкими полосками, «другое» последним) и заголовком по уверенности:
«Уверены: это базальт» / «Скорее всего базальт» / «Похоже на базальт, но не уверены». Под score/тиром подпись:
«Вероятность определения по фото, не состав камня. Редкость считается по правилам и от процентов не зависит.»

Score и тир не тронуты — они по-прежнему из `cards` (воркер считает порогами, spec §4.3). В клиенте нет ни одного
числа-порога: band, шаг округления, минимум и потолок кандидатов — из `identificationCandidates` / `identificationBand`
в `@lithos/shared` (`packages/shared/src/identification.ts`, не менялся). Только `apps/mobile/**` + этот артефакт.

### Источник данных
1. **Сама карточка**: `cards.rock_class` + `score_breakdown.meta.confidence` + `meta.alternatives` (воркер кладёт их
   в `rules()`, `apps/worker/src/pipeline.ts`). `parseIdentificationMeta(rock_class, score_breakdown)` в `card-types.ts`
   собирает `{ primary, confidence, alternatives }` и проверяет его `ScanResultSchema.shape.rock_class.safeParse`
   (zod из shared): порода вне enum, confidence вне [0, 1], кривые alternatives или отсутствие `meta.confidence` → null.
   Результат — `CardRow.identification` (рядом с `split_recommended`). Ни одного запроса, ни гонок: primary = rock_class
   по построению, после escalation карточка приходит новой через watcher T2.2 и список обновляется сам.
2. **Запасной путь** для старых карточек без meta — `scan_results` (последний вердикт: escalation, иначе main),
   читается **один раз** при появлении карточки без meta (не на каждый тик watcher'а).

## Проверка

Автоматически (зелёные): `pnpm --filter mobile typecheck`, `pnpm --filter mobile test` (99, из них 14 по теме),
`pnpm lint`, `npx expo export --platform ios` (бандл собрался, `dist` удалён).

### На телефоне
1. Камера → фото → «Определить». На Result сразу с карточкой: «Скорее всего …», крупная строка primary с процентом
   и полоской цвета тира, 1–4 кандидата тонкими полосками, «другое» приглушённо; под score — серая подпись. Скачка
   вёрстки при появлении списка нет. Score и тир — те же, что были бы без списка.
2. Ступень `escalation`: плашка «Уточняем» и текст «порода, проценты и карточка могут уточниться»; после финала список
   обновляется сам вместе с карточкой (Realtime/polling), без перезахода и без запроса scan_results.
3. «Открыть карточку»: секция «Порода» — заголовок + список + группа пород; в «История версий» при уточнении,
   изменившем список, — строка «было: …» под «Уточнение».
4. Старая карточка (до T5.0, без meta): на Result — на миг skeleton, затем список primary X % + «другое» (или порода
   строкой, если scan_results нет/невалиден/primary не совпал с карточкой); на Card — то же без skeleton.
5. VoiceOver/TalkBack: строка читается как «Базальт: 80 процентов, основной вариант»; полоски не озвучиваются.

## Решения
- **Название породы в заголовке со строчной** («Скорее всего базальт»): нарицательное; в строках — как в справочнике.
- **Один источник правды для списка — карточка.** `identificationCandidates` из shared читает только `rock_class`,
  поэтому клиент передаёт ему `{ rock_class }` (приведение к `ScanResult`, задокументировано в `candidatesOf`).
- **Согласованность заголовка и списка.** Из meta — по построению. Из scan_results — только при `primary ===
  cards.rock_class`, иначе порода строкой без списка (гонка: результаты уже от escalation, карточка ещё от main).
- **reason показываем как есть и только если он есть** (`numberOfLines={1}`, серым курсивом). Клиент не переводит и
  не фильтрует: язык reason — ответственность промпта воркера **main-v3** (`renderMainSystem(userLanguage)`);
  до его выката модель может вернуть английский текст — это ожидаемо.
- **«было: …» — по спискам, не по породе**: сдвиг только процентов тоже виден.
- **Подпись про вероятность — под score/тиром**, а не между списком и score: hero не рвётся.

## Ревью (закрыто)
- MAJOR 1 — лишний `fetchScanResults` на каждое обновление карточки: источник — `cards.score_breakdown.meta`
  (`parseIdentificationMeta`, zod-safe), scan_results — один раз и только без meta; early-return в эффекте возвращён.
- MAJOR 2 — заголовок vs список при гонке: `cardIdentification` показывает список из scan_results только при
  `primary === cards.rock_class`, иначе строка породы; тест «гонка → null».
- MAJOR 3 — reason только если есть; зависимость от промпта main-v3 отмечена выше.
- MINOR — единый формат «имя · N %» (`candidateLabel` → `label` в компоненте, свой литерал убран); мёртвый
  `hideHeadline` удалён, на CardScreen список заменяет «Порода: X»; склонение через `pluralRu` (комментарий про
  `IDENTIFICATION_PERCENT_STEP`); `useMemo` по rows для identification/splitRecommended; `IDENTIFICATION_NOTE` под
  score/тиром; skeleton вместо скачка вёрстки; артефакт переименован в T5.1.
