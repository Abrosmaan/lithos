# T2.2 — Клиент: результат и карточка (+ клиентская часть T2.3 «Раскол»)

Статус: **код готов, проверки зелёные, ревью-замечания закрыты; ждёт воркер T2.1 и ручную проверку на телефоне** · 2026-09-08

## Что сделано

Экраны **Result → Card → Collection(заглушка)** и поток раскола **Card/Result → Safety → Camera → Review → Result** с дельтой score. Только `apps/mobile/**`; балансовых чисел в клиенте нет — потолки слоёв, русские справочники и `finalSplitRecommendation` импортируются из `@lithos/shared`.

### Контракт с воркером (T2.1), на который опирается клиент
Сверено с `docs/tasks/T2.1.md` «Контракт для клиента» (воркер готов); три расхождения, названные там, закрыты на стороне клиента (обёртка `raw_json`, коды `photo_unavailable`/`parent_not_found`, nullable `score/tier`).
- `lithos.scans.stage`: `preflight → gate → main → escalation → rules → done | failed`; при `failed` — `scans.error ∈ not_rock | blurry | dark | too_far | screen_photo | multiple_objects | photo_unavailable | parent_not_found | dlq` (`multiple_objects` зарезервирован, воркер сейчас не выдаёт; неизвестный код показывается как `dlq`). `photo_unavailable` → «Не удалось получить фото — переснимите…»; при `parent_not_found` «Переснять» начинает обычный скан, не раскол.
- `lithos.cards` — одна строка на `scan_id` (upsert, `cards.id` стабилен), появляется вместе с `stage='escalation'` (предварительная — плашка **«Уточняем»** строго при `stage='escalation'`) или сразу с `stage='done'` (финал). Карточка при другом не-финальном `stage` (теоретически) показывается без плашки с подписью «досчитываем». `tier`/`score` могут быть `null` (без гео → «Без редкости»), `verification = pending_review` → тир «?», `provisional = true` → «Предварительно», `hidden = true` → «Была раскрыта».
- `lithos.scan_results (scan_id, stage, raw_json)` — история версий (main → escalation, `revision_note`). Воркер пишет `raw_json = { result, meta: { used_fallback, … } }` (`apps/worker/src/pipeline/types.ts`); клиент разворачивает `result`, допускает и «голый» `ScanResult`; `meta.used_fallback` → пометка «резервный провайдер».
- Рекомендация раскола: сначала `cards.score_breakdown.meta.split_recommendation.recommended` (воркер кладёт туда `finalSplitRecommendation`); если поля нет — из `scan_results`: `raw_json` по `ScanResultSchema` → `finalSplitRecommendation(result)` (модель **и** правила), при невалидной схеме — поле модели. Берётся последний вердикт (escalation, иначе main).
- `cards.shape` = `{ ...result.shape, surface }` — поверхность читаем из `shape.surface`.
- Раскол: клиент пишет `scans.parent_card_id`; гео и тесты не спрашивает — воркер берёт от родителя (dev-plan T2.3). Дельта — `score_breakdown.split_delta` (`splitDelta`), запасной путь — `cards.score` родителя vs ребёнка.
- Возраст региона — `geo_cache.age_range` по `cards.cell_id` (политика чтения есть в 0001); нет строки — блок скрыт.

### На телефоне (после того как воркер T2.1 запущен и в Dashboard открыта схема `lithos` + anonymous sign-ins — см. T1.4)
1. Камера → 1–3 фото → «Определить». Экран Result: «Определяем…» с подписью ступени; ждать ≤ 5 с до карточки (замер — человеком, dev-plan T2.2 приёмка).
2. Если воркер ушёл в Escalation — карточка с плашкой «Уточняем», потом обновляется сама (Realtime; если Realtime для схемы не включён — polling, визуально то же, задержка до 2–10 с).
3. Отказы: снять стену/ладонь → «Похоже, это не камень»; фото с экрана → «Фото с экрана не принимаем»; «Переснять» → камера.
4. «Открыть карточку»: тап по имени → своё имя → «Сохранить» → в Table Editor `cards.user_name`; тап по «как посчитано» → четыре слоя; фото листаются; «История версий» при наличии escalation.
5. «В коллекцию» → список; тап → карточка.
6. Раскол: на карточке с рекомендацией → «Расколоть и пересканировать» → экран безопасности (кнопка 5 с) → камера с подсказкой «Раскол» → Review без тестов → Result с «После раскола: было N → стало M». Второй раскол — без экрана безопасности. В Table Editor: `scans.parent_card_id` заполнен.
7. Выключить сеть на Result → «Нет связи» + «Обновить»; включить → продолжает.

## Решения
- **Realtime + polling, а не только polling.** Подписка на `lithos.scans`/`lithos.cards` (публикация в 0001); подтверждение ждём 3 с, иначе polling 2 с с backoff ×1.5 до 10 с. На событие — перечитываем строки, а не берём payload (RLS/фильтры могут урезать). После `done/failed` наблюдение останавливается.
- **Фаза экрана — по `stage` и наличию карточки** (`resultPhase`): `done` без строки `cards` трактуется как «ещё определяем» (гонка записи), не как ошибка.
- **Рекомендация раскола — из `cards.score_breakdown.meta`, с запасным путём через `scan_results`**: `finalSplitRecommendation` из shared требует полный `ScanResult`, поэтому `raw_json` валидируется `ScanResultSchema`; при провале — поле модели (мягкая деградация, без падения экрана).
- **Три факта**: порода + группа; главное включение — засчитанное (из `breakdown.composition.inclusions`, по баллам), иначе форма; место — по `breakdown.place.reason` (странник с механизмом по-русски). Включения показываются с `extent` по-русски, без процентов и без confidence (spec §5, §6.5).
- **Даты без Intl** (Hermes без локалей на части Android) — свой форматтер «7 сен 2026».
- **`metro.config.js`** вместо переписывания импортов в shared (shared — ESM для воркера, `./x.js` там обязателен).
- **Цвета тиров в `theme.ts`** — оформление; пороги и названия тиров — из shared.
- **Раскол**: гео и тесты не спрашиваем (dev-plan T2.3: воркер берёт от родителя), `geo: null`. `parentCardId` живёт в черновике, а не в params навигации; параметр камеры гасится после чтения.
- **«В коллекцию»** — карточка уже в БД (пишет воркер), кнопка только отмечает локально и ведёт в список.
- **Кнопка «Коллекция» на камере** — маленькое расширение, чтобы карточки были достижимы без нового скана (иначе в прототипе нет входа в коллекцию).
