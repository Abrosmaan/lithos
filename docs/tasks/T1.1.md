## Принятые решения (интерпретации spec)

**Форма (§6.1).**
- Берётся максимум из подходящих строк, не сумма: `natural_hole` 20 > силуэт 15 > `banded` 10 > сфероид/яйцо 8 > обычная галька 3. Из-за этого фактический максимум слоя — 20, хотя spec пишет «0–25». Зафиксировано как расхождение; `SHAPE_LAYER_MAX=25` оставлен на случай, если редактор добавит строку.
- «Куриный бог» — по `shape.natural_hole` **или** тегу `natural_hole` (модель может поставить любое из двух).
- «Узнаваемый силуэт» 15 — **только** по закрытым тегам `heart`/`crescent`. Свободный текст `recognizable_silhouette` в score не участвует (модель может написать «none» — текст недетерминирован), он только для карточки/лора.
- Обычная галька 3 — базовая строка для любого камня (в том числе угловатого): в spec нет нуля для формы.

**Место (§6.2).**
- Совпадение с литологией считается **детерминированно** по `geo.expected_rocks`, а не по флагу модели `provenance.matches_local_geology` (S4 — «проверка странник/антифрод по геоконтексту»; флаг модели легко подделать промптом/фото). Флаг модели используется только как дополнительный сигнал в `escalationTriggers`.
- Совпадение считается и по базовой литологии (`ROCK_CLASS_BASE`): Macrostrat говорит «basalt», модель — `amygdaloidal_basalt` → совпадает. Аналогично `vesicular_basalt↔basalt`, `flint↔chert`, `coquina/fossiliferous_limestone↔limestone`, `greywacke↔sandstone`, `ignimbrite↔tuff`. Добавлена цепочка `flint → chert → limestone` (`baseClass` разрешает цепочки): флинт в известняковом/меловом регионе совпадает с литологией. Эквивалентности `quartz_vein→quartzite` и `volcanic_breccia→tuff` убраны (разный генезис).
- Странник: порода не совпадает, `wanderer_mechanism` не null **и** есть в `geo.wanderers` → 20, `wanderer=true`. Механизм заявлен, но не из списка зоны → 0, `geo_anomaly=true`, reason `mismatch_implausible` (иначе модель могла бы «объяснить» любую породу).
- **Повсеместные породы** (`UBIQUITOUS_ROCK_CLASSES`: agate, chalcedony, jasper, chert, flint, quartz_vein, geode, concretion, fossil, petrified_wood) — вторичные/конкреционные, их нет в литологии Macrostrat как самостоятельных юнитов. При наличии гео: место 5, reason `ubiquitous`, `geo_anomaly=false`, `wanderer=false` (механизм странника не применяется). Расширение сверх spec §6.2, решение T1.1, помечено в коде.
- `unknown`, `unknown_igneous`, `unknown_sedimentary`, `unknown_metamorphic` — все одинаково: reason `unknown_class`, 0 баллов, `geo_anomaly=false` (сравнивать не с чем, группового сопоставления нет).
- `share` в `expected_rocks` валидируется: приводится к [0, 1]; NaN / не число → запись пропускается (как будто породы нет в списке).
- **Без гео** (`geo === null` или `expected_rocks` пуст, в т.ч. `source='none'`): слой 0 с reason `no_geo`, `has_geo=false`, **`score` и `tier` = null** (spec §4.1 «карточка без score»). Для эскалации и логов всегда считаются `internal_score` / `internal_tier`.
- **Гео-аномалия** (порода не совпала, механизма нет или он не из `geo.wanderers`): базовый бакет состава = 0 с reason `geo_anomaly`, а не «единичная 30» — карточка уходит на ревью, премировать её нельзя. Фиксированные бонусы агат/окаменелость применяются **до** этой проверки: их классов в литологии Macrostrat не бывает, иначе они всегда были бы аномалией.

**Состав (§6.3).**
- Бакет по `share` ожидаемой породы (или её базовой литологии; при нескольких совпадениях — максимальная доля): ≥0.5 → 5, [0.15; 0.5) → 10, [0.03; 0.15) → 20, <0.03 или отсутствует → 30 («единичная», только для странника — при аномалии см. выше). Границы — включительно снизу. Сами числа границ (0.5/0.15/0.03) в spec не заданы — расширение T1.1, помечено в коде. Для повсеместных пород: есть совпадение через `ROCK_CLASS_BASE` → обычный бакет по share; нет → бакет «редкая» 20 (не «единичная» 30). Агат/окаменелость — фикс-бонусы как раньше.
- Без гео база 0 (reason `no_geo`), а не 30: иначе выключенный GPS давал бы +30. `unknown_*` — база 0.
- Фиксированные бонусы **заменяют** бакет, не суммируются: агат 30, окаменелость 40. Окаменелость = `rock_class ∈ {fossil, petrified_wood}`. `fossiliferous_limestone` и `coquina` — обычные породы, база по бакету. Включение `fossil_fragment` даёт **только** баллы включения ×2 (при confidence ≥ 0.6), базу 40 не включает: известняк (share 0.3) + `fossil_fragment` traces → 10 + 3×2 = 16. Бонусы не зависят от гео («редкие везде»).
- Включения: только `confidence ≥ 0.6` (включительно); ниже — не существуют для score (и для `shouldRecommendSplit`). Баллы 3/7/12 по extent, множители из `INCLUSION_MULTIPLIERS`.
- Множитель «миндалины с цеолитом» ×1.5 применяется к `zeolite` всегда — в контексте пляжных камней цеолит практически всегда в миндалинах; завязываться на свободный текст `location` отказался (недетерминированно).
- Множитель «кварцевая друза» ×1.5: добавлено значение минерала `quartz_druse` (закрытый enum вместо распознавания слова «друза» в `evidence`), плюс `amethyst` ×1.5 (аметист — всегда друзовый/кристаллический кварц). Обычный `quartz` — ×1.
- Сумма слоя округляется (`Math.round`) до целого, затем потолок 45. В breakdown сохраняются `raw` и `capped`.

**Качество (§6.4).** `fresh_split` 6; `has_scale_photo` 2; «прошёл мини-тесты» = **и** `weight`, **и** `scratch` не null → 2. Ответ «мокрый/сухой» баллов не даёт (в §6.4 его нет; §4.1 «мини-бонус» трактован как эти же 2 балла).

**Тиры.** По порогам `TIER_THRESHOLDS` (≥ min), `MAX_SCORE=100`. Теоретический максимум с текущими таблицами — 95 (20+20+45+10), легендарный (85) достижим. Все таблицы — `as const`/readonly: мутация из воркера — ошибка компиляции.

**Раскол (§7).** `shouldRecommendSplit`: форма ≤ 8 и нет засчитанных включений; **не** предлагаем при `surface ∈ {fresh_split, polished}` (уже расколот / окатанная поверхность ценна) и `rock_class ∈ {fossil, petrified_wood, geode, agate}` (ценны целиком). Итоговая рекомендация для клиента — `finalSplitRecommendation(result) = result.split_recommendation.recommended && shouldRecommendSplit(result)`: модель и правила должны согласиться.

**Эскалация (ai-pipeline §3 S3).** Идентификаторы триггеров: `tier_rare_or_above`, `confidence_band` (0.45–0.65 включительно), `fossil_claimed` (порода `fossil`/`petrified_wood` или включение `fossil_fragment` с любым confidence), `rare_inclusion_claimed` (порода `agate`/`geode`, включения `quartz_druse`/`amethyst`/`native_copper` с любым confidence), `geology_mismatch` (порода не совпадает с литологией и механизм либо не заявлен, либо не из `geo.wanderers` — те же случаи, что дают `geo_anomaly`). Флаг модели `provenance.matches_local_geology` **не учитывается**; без гео триггер не срабатывает. Триггер «пользователь оспорил» — на уровне очереди `scan_dispute`, здесь его нет.

**Confidence.** Используется только в сравнениях с порогами (`>= 0.6`, полоса 0.45–0.65). Ни один балл не вычисляется из confidence.

## Правки словарей

**Породы (60 → 66, только добавления).** Добавлены: `trachyte` (щелочной вулканит, распространён в кавказских/средиземноморских регионах), `ignimbrite` (спёкшийся туф, отдельная литология в Macrostrat), `syenite` (плутонический аналог трахита, есть в номенклатуре IUGS), `greywacke` (самая частая «серая» галька флишевых побережий, у Macrostrat отдельная литология), `marl` (мергель — ловушка «известняк/глина», часто на побережьях), `migmatite` (щитовые регионы: Карелия, Скандинавия — очень частый валун). Без них модели пришлось бы натягивать `unknown_*`.

**Рассмотрены и не добавлены:** `porphyry` (текстура, не состав — маппится на granite/andesite/rhyolite), `arkose`/`oolitic_limestone`/`radiolarite`/`phosphorite`/`bauxite` (подтипы, редко определимы по фото), `kimberlite`/`blueschist`/`skarn` (слишком редки для пляжной коллекции; `hornfels` покрывает контактовые породы), `slag`/`sea_glass`/`concrete` (не породы — отсеивает Gate `is_rock=false`; если бы были в enum, «единичная» база давала бы им 30 баллов), `meteorite` (вне scope прототипа).

**Оставлено с оговоркой:** `dolomite` как порода (современный термин — «dolostone»; mindat тоже допускает «dolomite rock»). Переименование сломало бы параллельные задачи; при этом минерал `dolomite` в `MINERALS` — тот же токен в другом словаре, коллизии в коде нет (разные enum'ы). `claystone` и `mudstone` оба оставлены (в spec-стартовом списке; по фото различимы плохо — модель предпочтёт `mudstone`).

**Минералы (41 → 45).** Добавлены: `quartz_druse` (для множителя §6.3, см. выше), `opal` (агаты, окаменелое дерево, миндалины), `prehnite` (типичный спутник цеолитов в миндалинах базальтов Кавказа/Декана — частая ошибка «зелёный цеолит»), `kyanite` (синие пластины в кристаллических сланцах — узнаваемое включение). Не добавлены: `native_gold`/`native_silver` (приглашение к галлюцинации; спорные заявки покрывает `pyrite`/`chalcopyrite` + эскалация на `native_copper`), `staurolite`/`andalusite`/`apatite` (редко видимы по фото).

**Теги формы:** 12, без изменений. `banded` (полосчатость) — единственный тег «рисунка», как в spec §6.1.

## Требует решения человека

- **Аметист ×1.5.** В spec §6.3 множитель ×1.5 назван для «кварцевой друзы». Аметист — фиолетовый кварц, в природе практически всегда друзовый/кристаллический, поэтому трактуем `amethyst` как «кварцевую друзу» из spec и даём ×1.5. Если редактор хочет ×1 — убрать строку из `INCLUSION_MULTIPLIERS`.
- **`geode` в `RARE_CLAIM_ROCK_CLASSES`.** ai-pipeline §3 S3 эскалирует «редкое включение (агат, друза, самородный металл)». Жеода — это заявка друзы на уровне породы, поэтому включена в список для S3 наравне с агатом. На score это не влияет.

## Не сделано / открытое

- Расхождение «форма 0–25» vs фактический максимум 20 при правиле «максимум из подходящих» — нужно решение редактора: либо принять 20, либо добавить строку на 25 (например, «сквозное отверстие + узнаваемый силуэт»).
- Слой «место» по spec — только тег странника и аномалия; веса «человеком завезён» (`human_imported`) не отличаются от других механизмов — по букве spec это 20 баллов, что спорно (привезённый гранит на пляж = странник). Оставлено как в spec; T1.2 решает, включать ли `human_imported` в `wanderers` зоны.
- Множитель цеолита не проверяет, что цеолит именно в миндалинах (см. решения). Если появятся сканы с цеолитом в жилах — пересмотреть.
- Поле `wet` в `UserTests` не влияет на score; в промпт передаётся (T1.3).
- `ScanResultSchema` не менялась (ограничение задачи); `recognizable_silhouette` остался в схеме, но score его не читает. `Deep<>`-фабрика в тестах — локальная, в экспортах её нет.
- Не прогонялся `pnpm eval` (golden set появится в T2.x); балансовые таблицы не калибровались на реальных сканах — стабильность тира ≥ 90% (spec §6.5) проверять после T2.1.
- Корневой `pnpm typecheck` красный из-за `apps/worker/src/llm/providers.ts` (T1.3, в работе) — не в границах T1.1.
- В git не коммичено (по условию задачи).
