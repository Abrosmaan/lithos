# T0.1 — Монорепо и окружение

Статус: **готово** · 2026-09-07

## Что сделано

- pnpm-монорепо (`pnpm-workspace.yaml`, `.npmrc` с `node-linker=hoisted` — иначе Metro не видит зависимости), корневые `typecheck` / `lint` (ESLint 9 flat + typescript-eslint) / `test` / `dev` / `db:migrate`.
- `packages/shared` — заглушка с константами очередей и стадий; схемы и score — T1.1.
- `apps/mobile` — Expo SDK 57 (blank-typescript), `App.tsx` с экраном камеры (expo-camera, запрос разрешения на русском). Установлены зависимости под следующие волны: expo-location, expo-image-manipulator, expo-file-system, expo-crypto, expo-image, react-native-maps, supabase-js, async-storage, react-navigation. `app.json`: имя Lithos, bundle id `com.abrosmaan.lithos`, тексты разрешений камеры/гео.
- `apps/worker` — Node 20 + TS, `pg` через session pooler, hello-цикл: читает `scan_interactive → scan_dispute → scan_batch` (`pgmq.read`, lease 60 с), логирует `scan_id`, `pgmq.delete`. Структурный JSON-лог без секретов. Dockerfile + `docker-compose.yml` (host network, `lithos-worker`, mem_limit 512m).
- `supabase/migrations/0001_schema_init.sql` — схема `lithos`, enum'ы `scan_stage`/`card_state`/`card_verification`, таблицы из dev-plan §3 (`users`, `scans`, `scan_photos`, `scan_results`, `cards`, `geo_cache`, `diary`), RLS с политиками «своё по auth.uid()», `lithos.current_user_id()`, RPC `lithos.enqueue_scan(scan_id, queue)` (security definer — клиент не имеет доступа к схеме pgmq), три очереди pgmq, публикация Realtime для `scans`/`cards`.
- `supabase/migrations/0002_storage.sql` — приватный бакет `lithos-photos` (5 МБ, jpeg/png/webp), политики «своя папка `<user_id>/…`».
- `scripts/db-migrate.mjs` — идемпотентный раннер через pooler, журнал `lithos.schema_migrations`. **Миграции применены к prod-Supabase.**
- `.env.example`, `README.md`.

## Проверка

- `pnpm typecheck` — зелёный (shared, worker, mobile). `pnpm lint` — зелёный.
- Воркер: `pgmq.send('scan_interactive', …)` → `pnpm --filter worker start` → лог `scan received … scan_id=…` → сообщение удалено из очереди → лог `queues empty`.
- На телефоне: `pnpm --filter mobile start` → Expo Go → запрос камеры → живое превью с подсказкой «Наведите на камень».

## Решения

- **Pooler вместо direct для воркера.** Session pooler (IPv4) работает и с мака, и с VPS; direct — IPv6-only. Порядок в `config.ts`: `WORKER_DB_URL` → `SUPABASE_DB_POOLER_URL` → `SUPABASE_DB_URL`.
- **pgmq живёт в схеме `pgmq`**, не в `lithos` — ограничение расширения. Имена очередей — из dev-plan, других пользователей pgmq в инстансе нет. Клиенту доступ к pgmq не даём, только RPC.
- **`rock_class`/`tier` в БД — text**, не pg-enum: справочник живёт в `packages/shared` (источник истины), дублировать 60 значений в SQL — расхождение при каждом изменении.
- **Realtime** через `supabase_realtime` publication на `scans` и `cards` — клиент фильтрует по `scan_id`.
- Плановый «Node-воркер на Fly.io/Railway» заменён на общий Hetzner VPS (INFRA.md §2) — ноль новой инфры.
- TypeScript в mobile — 6.0 (из шаблона Expo 57), в shared/worker — 5.9. Тайпчек проходит в обоих; унифицировать при первом конфликте.

- `pnpm test` пока нечего гонять (vitest подключён, тестов нет) — появятся с T1.1/T1.3.
- Google Gemini API-ключа в аккаунте нет (INFRA.md) — нужен до T1.3 для второго провайдера.
- EAS-проект не создан (`eas init`) — нужно до T4.2; для Expo Go не требуется.
- На телефоне экран камеры не проверялся автоматически — ручная проверка человеком.
